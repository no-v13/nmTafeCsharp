1. 비즈니스 기능 완성하기 (Part A)
상세 정보 연결하기:

카페로 치면: 아메리카노에 '사이즈'나 '시럽 추가' 옵션을 붙였던 것처럼, Contractor와 Jobs 클래스에 시작일, 비용, 시급, 완료 여부 같은 속성 칸들을 화면 입력창(TextBox, DatePicker)과 1:1로 짝지어주는 작업입니다.

계약직 배정하기 (Assign Contractor):

카페로 치면: 손님이 원하는 음료 옵션을 고르듯, 드롭다운(ComboBox)에서 지금 놀고 있는(대기 중인) 계약직을 콕 집어서 선택한 일자리(Job) 객체 안의 전용 칸에 쏙 집어넣어 묶어주는 기능입니다.

일자리 완료 처리 (Complete Job):

카페로 치면: 주문이 끝나면 가방을 비우듯, [완료] 버튼을 누르면 일자리의 isDone 상태가 true로 바뀌고, 그 일에 묶여있던 계약직을 다시 풀어주어(null로 비우거나 상태 변경) 다른 일에 또 투입될 수 있게 해주는 로직입니다.

🔍 2. 조회 및 필터링 기능 구현하기 (Part B & C 전반)
대기 계약직 / 미배정 일자리 필터링:

카페로 치면: 장바구니 리스트를 foreach로 훑으면서 조건에 맞는 것만 쏙쏙 골라내던 것과 똑같습니다. "지금 일 안 하고 있는 사람 누구야?", "아직 사람 안 구해진 빈 일자리 뭐야?" 하고 리스트 서랍장을 if문으로 탈탈 털어 화면에 보여주는 기능입니다.

비용 범위 검색 (Cost Range Search):

카페로 치면: 가격대별 메뉴 찾기입니다. 사용자가 최소 비용과 최대 비용을 입력하면, 일자리 서랍장(List<Jobs>) 속을 foreach로 돌며 if (job.totalSalary >= min && job.totalSalary <= max) 조건에 맞는 일자리들만 싹 모아서 화면에 띄워주는 검색 기능입니다.

🧪 3. 테스트 및 문서화 준비하기 (Part B & Part C)
테스트 계획서 (Part B):

"이 프로그램이 고장 안 나고 잘 돌아가는지 어떻게 검사할 것인가?"를 말로 미리 계획서 문서에 적어두는 단계입니다. (테스트 케이스 설계 기법, 테스트 데이터 기획 등)

UI 수동 테스트 및 단위 테스트 (Part C):

수동 테스트: 직접 마우스로 버튼 누르고 입력해보며 에러가 안 나는지 눈으로 확인하고 표에 적기.

단위 테스트(Unit Test): Visual Studio에서 테스트 전용 프로젝트를 하나 더 만들어서, 우리가 짠 핵심 로직(비용 검색이나 계약직 배정 함수)이 제대로 작동하는지 컴퓨터가 알아서 자동 검사하게 시키는 스크립트 작성하기.

디버거 증적 및 보고서:

코드가 멈췄을 때(중단점/Breakpoint) 변수 안에 값이 잘 들어있는지 스크린샷 찰칵 찍어두고, 최종 결과 보고서 파일로 묶어서 제출하기.
